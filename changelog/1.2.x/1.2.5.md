# 1.2.5 — 2026-05-22

## Fixed

- **`translateQuery` `cat:` extraction inside parens** ([#14](https://github.com/cyanheads/arxiv-mcp-server/issues/14)) — extracting a `cat:` operand from inside a parenthesized group left a dangling boolean operator or an empty `( )` group, both of which FTS5 rejects. The previous per-iteration `dropPrev` heuristic only triggered when the next token was `undefined` or another `cat:`; it didn't cover `(cat:cs.LG OR term)`, `(term OR cat:cs.LG)`, `(cat:cs.LG)`, `(cat:cs.LG OR cat:cs.AI)`, etc. The new `cleanupDanglingOps` runs after the main translation pass and iterates to a fixed point: collapses any `( )`, then drops any `AND`/`OR`/`NOT` whose left neighbor is `(`, an operator, or the array start, or whose right neighbor is `)` or the array end. Re-runs until no changes, so cascading cleanups (collapse → newly-adjacent operator → drop → newly-empty group → collapse) all converge without per-shape special cases. The defense-in-depth catch added in [v1.2.4](changelog/1.2.x/1.2.4.md) is now unreachable for the documented `cat:`-in-parens shapes; it stays in place to guard against future translator regressions.
