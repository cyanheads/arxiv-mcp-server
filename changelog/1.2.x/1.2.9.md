# 1.2.9 — 2026-05-29

Mirror schema bumped 1→2. Both fixes share the version bump and an in-place, batched, resumable backfill migration that upgrades existing v1 databases on first open — no re-harvest required.

## Fixed

- **`arxiv_search` sort by `submitted`/`updated` on mirror** — `rawToRow` now calls `normalizeDateToIso()` on `published`, `updated`, and `latest_version` before persisting. OAI version dates (RFC 2822, e.g. `Wed, 31 Oct 2018 14:58:30 GMT`) and YYYY-MM-DD datestamp fallbacks are both normalized to ISO 8601 (`2018-10-31T14:58:30.000Z`), so `ORDER BY papers.published|updated` is chronological rather than lexicographic over the weekday prefix. Previously "newest first" floated every `Wed, 31 …` row to the top regardless of year. ([#18](https://github.com/cyanheads/arxiv-mcp-server/issues/18))

- **Category-only mirror queries taking ~2 minutes** — `paper_categories(category, paper_id, updated)` junction table replaces the unindexable `LIKE '% cat %'` filter on the space-joined `categories` column. COUNT and membership lookups on the pure-category path now hit `paper_categories_cat_updated_idx ON paper_categories(category, updated)`; the composite trailing column also lets single-category ordered browse page straight off the index without a `papers` scan or temp-b-tree sort, even for rare categories. ([#19](https://github.com/cyanheads/arxiv-mcp-server/issues/19))

## Changed

- **`MIRROR_SCHEMA_VERSION`** 1→2 (`schema.ts`, `schema.sql`).
- **`MirrorStore.open`** runs `migrateToV2()` when `schema_version < 2` — streams rows in 5 000-row batches with per-batch commits so WAL stays bounded on the 3 M-row production DB. Writes `schema_version = 2` only after both the date-backfill and junction-population steps complete; an interrupted run restarts from the top safely.
- **`normalizeDateToIso`** exported from `mirror/index.ts` for use in tests and scripts.
