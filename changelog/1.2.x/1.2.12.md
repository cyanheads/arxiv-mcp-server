# 1.2.12 — 2026-06-01

## Fixed

- **Mirror refresh event-loop blocking** — the scheduled HTTP-mode OAI-PMH refresh now runs in a child process via `runRefreshSubprocess` (`src/services/arxiv/mirror/refresh-subprocess.ts`). The harvest's synchronous SQLite writes (`applyBatch` transactions, the closing `SELECT COUNT(*)`) execute in the child, not on the request event loop, so `arxiv_search` and `arxiv_get_metadata` stay responsive throughout the harvest window. ([#22](https://github.com/cyanheads/arxiv-mcp-server/issues/22))

## Added

- **`ARXIV_MIRROR_REFRESH_TIMEOUT_MS`** (`src/config/server-config.ts`) — caps a single refresh run; default `7200000` (2 h). On overrun the child receives SIGTERM, then SIGKILL after a grace period.
