# 1.2.16 — 2026-07-26

## Changed

- **Version-aware ID resolution.** New `resolveRequestedIds()` helper (`src/services/arxiv/arxiv-service.ts`) matches each requested paper ID to a response/mirror record by its full versioned ID when one is pinned, falling back to base-ID/latest-version matching only for unversioned input. Applied at every site that previously matched on a version-stripped base ID.
- **`arxiv://paper/{paperId}`** now percent-decodes the URI segment before use — `UriTemplate.match()` hands handlers raw, un-decoded text, so a legacy ID's slash (`hep-th/9901001`) is now reachable via `arxiv://paper/hep-th%2F9901001` for the first time. A segment that decodes to blank (e.g. `%20%20%20`) is rejected with a new `empty_id` contract entry instead of reaching the arXiv API.
- **`@cyanheads/mcp-ts-core` `^0.10.9` → `^0.11.0`** — notable framework changes adopted:
  - Bundle packaging now strips platform-specific native bindings (`@duckdb/node-bindings-*`) from `.mcpb` output, in addition to the existing agent-doc strip — keeps the bundle cross-platform and under the 25 MB registry cap.
  - `bunfig.toml` supply-chain guard: `minimumReleaseAge = 259200` (3-day install delay) with `@cyanheads/mcp-ts-core` excluded, plus a Socket scanner (`@socketsecurity/bun-security-scanner`) wired into `[install.security]`.
  - `Dockerfile`: BuildKit cache mounts on every `bun install`, `oven/bun:1.3.14` pinned (was floating `1.3`), `ARG APP_VERSION` → OCI `image.version` label, and a `HEALTHCHECK` hitting `/healthz` via `bun -e fetch(...)` (the slim image ships no curl/wget).
  - `.gitignore`: `data/` anchored to `/data/` (was matching any nested `data/` directory).
- Re-synced framework scripts (`devcheck.ts`, `build-changelog.ts`, `clean-mcpb.ts`, `lint-mcp.ts`, `lint-packaging.ts`, `tree.ts`, `check-dependency-specifiers.ts`) and skills (`add-tool`, `api-canvas`, `api-config`, `api-linter`, `api-utils` + `parsing.md` reference, `api-workers`, `code-simplifier`, `design-mcp-server`, `field-test`, `git-wrapup`, `orchestrations` + workflow docs, `polish-docs-meta` + `package-meta.md`/`readme.md` references, `release-and-publish`, `techniques` + `outline-on-overflow.md` reference, `tool-defs-analysis`) to the 0.11.0 toolchain.

## Fixed

- **Explicit versioned IDs no longer silently resolve to a different version.** `arxiv_get_metadata` and the `arxiv://paper/{paperId}` resource were stripping every requested ID's version before matching it against the mirror or live response — an explicit `vN` could come back as whatever version the mirror happened to store, or whatever version a batch response's `Map` insertion order left standing ([#25](https://github.com/cyanheads/arxiv-mcp-server/issues/25), [#28](https://github.com/cyanheads/arxiv-mcp-server/issues/28)). A version-mismatched mirror hit is now a miss that falls through to the live API (or `not_found_ids`); a batch requesting two versions of the same base ID now returns both in their correct slots.
- **`arxiv_read_paper`'s mirror fallback** no longer substitutes a different stored version when a version-pinned `paper_id` is requested and the live API is unreachable — it now throws `ServiceUnavailable` (`reason: version_unavailable`, carrying `mirrorVersion`) instead of fetching and returning the wrong revision's HTML body ([#33](https://github.com/cyanheads/arxiv-mcp-server/issues/33)).
- **Whitespace-only paper IDs** are now rejected at the Zod schema layer (`.trim().min(1, …)`) across `arxiv_get_metadata` (scalar and array-element), `arxiv_read_paper`, and the paper resource — previously they passed the length check and consumed an arXiv API request slot before failing upstream ([#26](https://github.com/cyanheads/arxiv-mcp-server/issues/26)).
