# 1.2.3 — 2026-05-21

## Fixed

- **Dockerfile production stage** writes a minimal `tsconfig.json` (`{"compilerOptions":{"baseUrl":".","paths":{"@/*":["./dist/*"]}}}`) so Bun can resolve the `@/...` path alias the mirror lifecycle scripts import through (`@/config/server-config.js`, `@/services/arxiv/mirror/index.js`). The source `tsconfig.json` maps `@/*` to `./src/*`, but production only carries `./dist/*` — and v1.2.2 shipped the scripts but neither a `tsconfig.json` nor a `bunfig.toml`, so `docker exec arxiv-mcp bun run mirror:verify` failed with `Cannot find module '@/config/server-config.js'`. The minimal config is enough; the compiled `dist/` output has its own aliases already resolved by `tsc-alias` at build time and doesn't need this.

No source changes. `dist/` output is byte-identical to v1.2.2.

## Notes

- npm-installed copies (`bun add @cyanheads/arxiv-mcp-server`) still don't ship a runtime `tsconfig.json`, so `bun run mirror:init` from `node_modules/@cyanheads/arxiv-mcp-server/` would hit the same error. The realistic operator workflow (Docker pull, `docker exec ... bun run mirror:init`) now works end-to-end; the `bun add` + `mirror:init` path is an edge case that can be addressed in a future release by compiling the mirror scripts to JS at build time.
