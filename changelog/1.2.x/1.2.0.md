# 1.2.0 — 2026-05-21

Eliminates the ~3-second per-IP arXiv crawl-delay bottleneck for `arxiv_search` and `arxiv_get_metadata` on self-hosted instances. Mirror is opt-in — no behavior change without explicit configuration.

## Added

- **OAI-PMH metadata mirror (`src/services/arxiv/mirror/`)** ([#12](https://github.com/cyanheads/arxiv-mcp-server/issues/12)) — local SQLite + FTS5 store served via `bun:sqlite` (Bun runtime) or `better-sqlite3` (Node fallback). `harvester.ts` handles `ListRecords` resumption-token paging with daily expiry recovery via `from=<last_datestamp>` and honors `deletedRecord=persistent` tombstones. `query.ts` translates arXiv field-prefix syntax (`ti:`, `au:`, `abs:`, `cat:`, `all:`, `AND`/`OR`/`ANDNOT`) to FTS5 MATCH expressions and expands `cat:` group/archive codes against the static taxonomy. `store.ts` exposes batch upsert + FTS5 search + harvest-state read/write inside SQLite transactions. `runner.ts` orchestrates init/refresh with checkpoint persistence.
- **Mirror scripts** — `bun run mirror:init` (full harvest, idempotent + resumable; ~4.4h sequential against the ~3.04M-record corpus), `bun run mirror:refresh` (daily incremental, ~30s and <1 page), `bun run mirror:verify` (`PRAGMA integrity_check` + `quick_check`).
- **In-process refresh scheduler (HTTP only)** — when `ARXIV_MIRROR_REFRESH_CRON` is set, the server self-schedules the daily refresh via the framework's `schedulerService`. Single-instance constraint documented, not enforced. Stdio mode ignores the cron — operators wire `bun run mirror:refresh` to external cron / systemd / launchd.
- **Env vars** — `ARXIV_MIRROR_ENABLED` (default `false`), `ARXIV_MIRROR_PATH` (`./data/arxiv-mirror.db`), `ARXIV_MIRROR_REFRESH_CRON` (unset), `ARXIV_MIRROR_FALLBACK_LIVE` (`true`), `ARXIV_MIRROR_RECENT_DAYS_LIVE` (`2`), `ARXIV_MIRROR_OAI_BASE_URL` (`https://oaipmh.arxiv.org/oai`), `ARXIV_MIRROR_OAI_REQUEST_DELAY_MS` (`3000`).
- **Dependencies** — `better-sqlite3 ^12.10.0` (Node fallback), `node-cron ^4.2.1` (used by framework `schedulerService`). Dev: `@types/better-sqlite3 ^7.6.13`, `@types/bun ^1.3.14`, `@types/node-cron ^3.0.11`.

## Changed

- **`ArxivService.search` / `ArxivService.getPapers`** route to the local FTS5 store when `harvest_state.status='complete'`. Queries sorted by `submitted` descending within `ARXIV_MIRROR_RECENT_DAYS_LIVE` bypass the mirror to cover the nightly-update gap. ID-lookup misses optionally fall through to the live API (`ARXIV_MIRROR_FALLBACK_LIVE`). `arxiv_read_paper` is unchanged — HTML/PDF harvest is forbidden by arXiv's data policy.
- **Cold-start behavior** — `ARXIV_MIRROR_ENABLED=true` may be set at any point; reads transparently use the live API until the harvest reaches `complete`, then switch to the mirror with no restart.
- **`tsconfig.json`** — adds `bun` to `compilerOptions.types` so `bun:sqlite` resolves cleanly under `tsc --noEmit`.
- **Dev deps refresh** — `@types/node ^25.8.0 → ^25.9.1`, `vitest ^4.1.6 → ^4.1.7`.

## Notes

- **Ranking divergence.** FTS5 BM25 ≠ arXiv's internal ranking. `sortBy=relevance` against `mirror=on` vs `mirror=off` produces different top-K orderings — by design, documented as a behavior tradeoff.
- **Versions.** Mirror stores the latest version only; per-version requests via `arxiv_read_paper` continue to hit the live API.
