# 0.1.17 — 2026-05-08

## Fixed

- **`AbortSignal.timeout` misclassification in `ArxivService`** — fetch hangs (typically connection-layer arXiv throttling) raised a DOMException with `name: 'TimeoutError'` that fell through to the `serviceUnavailable` catch-all. The framework's default retry predicate then retried the same throttled connection, doubling caller-visible latency and upstream load. Production logs (2026-05-08) showed 60-90s totals on requests that should have failed at 15s. Now the catch arms on `search()`, `fetchArxivHtml()`, and `fetchAr5ivHtml()` detect `name === 'TimeoutError'` and throw `timeout(...)` with `data.timeoutMs`. `isArxivTransient` drops `Timeout` from the retry set — only `ServiceUnavailable` (5xx, raw network blips) and unknown non-McpError throws stay retryable.
