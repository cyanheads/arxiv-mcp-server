# 0.1.16 — 2026-05-05

Conformance pass on the error surface. Every non-baseline throw site (`RateLimited`, `InvalidRequest`) on every API-using tool and resource now declares a typed `errors[]` entry and resolves its recovery hint via `ctx.recoveryFor(reason)`. The framework's auto-classifier already mirrored `data.recovery.hint` to the wire when contracts existed; previously the contract was missing for these reasons on `arxiv_search`, `arxiv_get_metadata`, `arxiv_read_paper`, and `arxiv://paper/{paperId}`, so clients hit by an arXiv 429 or a malformed-ID 4xx received the error code without the next-move guidance. Closes the gap that lint couldn't catch (handler-text scan misses service-thrown reasons).

No wire-shape break — `error.code` and existing `data` fields are unchanged; the new fields are additive (`data.reason`, `data.recovery.hint`).

## Added

- **`rate_limited` contract entry** on `arxiv_search`, `arxiv_get_metadata`, `arxiv_read_paper`, and `arxiv://paper/{paperId}` — `code: RateLimited`, `retryable: true`, `recovery: "Wait for the cooldown indicated by error.data.retryAfter (seconds) before retrying."` Service `rateLimited` throws (200 OK with `Rate exceeded.` body and HTTP 429) now spread `ctx.recoveryFor('rate_limited')` into `data` so callers get the hint regardless of whether the service or the tool layer authored the throw.
- **`invalid_request` contract entry** on the same four surfaces — `code: InvalidRequest`, with per-surface recovery hints (`arxiv_search` points at field-prefix syntax; the metadata/read/paper surfaces point at ID format). Service `invalidRequest` throw (HTTP 4xx other than 429) now carries `reason: 'invalid_request'` plus the matching `ctx.recoveryFor()` payload.
