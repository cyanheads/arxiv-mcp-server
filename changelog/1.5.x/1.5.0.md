# 1.5.0 — 2026-07-27

## Changed

- **A `cat:` operand written inside `query` now expands through the category taxonomy on the live path** the same way it always has on the mirror. `buildSearchQuery` rewrites every `cat:` operand via `categorySearchTerm` before the request reaches arXiv — `cat:cs` now reaches the whole `cs.*` subtree instead of matching nothing, and `cat:astro-ph` reaches the same set the mirror has always returned. `effective_query` echoes the rewritten form. [#36](https://github.com/cyanheads/arxiv-mcp-server/issues/36)
- **A query `cat:` operand and the `category` input parameter now compose as separate, AND-ed filters on the mirror path**, matching how the live API has always composed them (`(… cat:X …) AND cat:Y`). `MirrorStore.search` takes `categoryGroups` — codes OR-ed within a group, groups AND-ed — in place of a single flat `categoryFilters` list that merged both inputs into one OR-ed set.

## Fixed

- **`co:` and `jr:` query prefixes now match on the mirror path.** `papers_fts` (schema v3) indexes `comment` and `journal_ref` alongside `title`/`authors`/`abstract`; previously both prefixes fell through to bare-token FTS matching against those three columns and matched nothing. [#37](https://github.com/cyanheads/arxiv-mcp-server/issues/37)

## Migration

Mirror schema bumps 2 → 3. `MirrorStore.open` drops `papers_fts` and its three sync triggers and rebuilds both from `MIRROR_FTS_SQL`, refilling the index from the rows already stored in `papers` — batched by rowid (5,000/batch), logging `mirror migration v2→v3 (fts rebuild): N/total rows` progress, and restarting from the beginning if interrupted. No re-harvest is needed. The rebuild runs before the store answers its first read, so the first start after upgrading a large mirror takes noticeably longer than usual. `bun run mirror:verify` now prints the schema version the file carries and exits non-zero if a migration didn't complete.
