# 1.5.2 — 2026-09-13

## Added

- **Offline mirror/live parity coverage** — eleven `arxiv_search` cases run through both backends over a fixture corpus, asserting identical `structuredContent` and `content[]`, the exact query string sent upstream, and that the mirror path issues no fetch. Replaces a live-API smoke test that only ran behind `ARXIV_MIRROR_PARITY=1`; each case builds its mirror from a fresh database, so schema creation and the v2/v3 migrations run on first creation too.
- **`bun run audit:fix`** — runs `bun audit fix` to patch vulnerable packages within existing ranges. Try it before `bun update <name>`, with `audit:refresh` last, since that one re-resolves every ranged dependency including the framework.
- **`CHANGELOG.md` and `changelog/` ship in the npm tarball.**

## Changed

- **Bun engines floor is `>=1.4.0`**, up from `>=1.3.0`, carried up from the framework's own floor.
- **The framework skill tree moved from `skills/` to `framework-skills/`** ([mcp-ts-core#428](https://github.com/cyanheads/mcp-ts-core/issues/428)) — Claude Code and Codex auto-load a plugin's root `skills/`, so installing this server's plugin handed the agent its development skills. Root `skills/` is now reserved for skills the server publishes to the agents that use it.
- **A 501 from an arXiv HTML, ar5iv, PDF, or OAI-PMH fetch fails fast** (mcp-ts-core 0.12.4) — `httpErrorFromResponse` attaches `data.retryable: false`, which keeps a method the upstream does not implement out of `withRetry` even though it still classifies as `ServiceUnavailable`.
- **A caller that disconnects mid-call reports `RequestCancelled` (-32011)** rather than `InternalError` (mcp-ts-core 0.12.4), and malformed tool arguments come back as a structured `InvalidParams` (-32602) error result instead of `ValidationError` (0.12.7).
- **Records logged from `setup()` reach the sink** (mcp-ts-core 0.12.5) — the logger buffers pre-init records and replays them, so the mirror-refresh scheduling line is no longer dropped.
- **An empty or whole-value `${…}` env value reads as unset** (mcp-ts-core 0.13.0) — an unsubstituted placeholder in an `ARXIV_*` variable takes the field's default instead of failing as a format error against the literal text.
- **`.env.example` documents the `ARXIV_MIRROR_*` block** and names all three `MCP_SESSION_MODE` values with `auto` as the framework default.
- **Plugin and bundle metadata** — `.claude-plugin/plugin.json` gains its schema reference, keywords, and author contact; `manifest.json` gains author contact. `lint:packaging` now checks MCPB `user_config` wiring and rejects an empty plugin `env` value, which would replace a variable the user exported (mcp-ts-core 0.13.0).
- **`devcheck`** gained a Worker typecheck lane and attributes `bun outdated` rows to the `package.json` key that declared them (mcp-ts-core 0.12.7), and parses Bun 1.4's `bun audit` output (0.12.9). Its `outdated` allowlist is empty and removed.
- **Issue forms** accept blank issues, route vulnerabilities to the private advisory form, and assign new issues to the maintainer.

## Fixed

- **`ARXIV_MIRROR_RECENT_DAYS_LIVE` is documented as a switch, not a date window** — any positive value routes every `sort_by=submitted`, descending search to the live API; `0` disables the bypass. The README also names `MCP_SESSION_MODE` and uses the tools' actual `sort_by` parameter name in place of `sortBy`.
