# 1.5.3 — 2026-09-19

## Added

- **`sessionMode: 'stateless'`** declared in `createApp()` ([#40](https://github.com/cyanheads/arxiv-mcp-server/issues/40)) — stdio, `bunx`/`npm`, and Docker now resolve the same session posture instead of only the Docker image's `ENV` doing so. `.env.example` sets `MCP_SESSION_MODE=stateless` as the active default to match.
- **`.github/workflows/codeql.yml`** — the one permitted GitHub Actions workflow; runs only while the repo's CodeQL default setup stays off.

## Changed

- **Tool error text closes with `(reason <reason> · retryable)` or `(reason <reason> · not retryable)`** whenever `error.data` carries a `reason` or a boolean `retryable` (mcp-ts-core 0.13.5). `rate_limited` and `version_unavailable` throws now set `data.retryable: true` explicitly so it reaches this text and `structuredContent.error.data`.
- **A malformed tool call is less likely to fail outright.** A client-added root key (e.g. a `toolCallId` or `_meta` some clients attach) is now dropped instead of rejected, and a case-style spelling of a declared parameter (`maxResults`) is rewritten onto the declared key (`max_results`) before validation (mcp-ts-core 0.13.4).
- **Argument rejections carry `data.reason: "invalid_arguments"` and a `Recovery:` line naming the offending field** in `content[]` (mcp-ts-core 0.13.3).
- **Upstream fetch failures against `arxiv.org/html`, `ar5iv`, and `arxiv.org/pdf` no longer put the request URL on `error.data`** by default (mcp-ts-core 0.13.4); none of the three `httpErrorFromResponse` call sites opt back in.
- **Retry classification (`isArxivTransient`) composes off the framework's `defaultIsTransient`** instead of a hand-rolled `ServiceUnavailable`-only check, so a future change to the transient code set or the `data.retryable === false` opt-out reaches these calls too.
