# 1.3.1 — 2026-07-26

## Added

- **`arxiv_search`** gains `submitted_from` / `submitted_to` — optional, inclusive UTC `YYYY-MM-DD` bounds on submission date. A window's upper bound closes at midnight of the day *after* `submitted_to` (arXiv compares against the paper's full-precision timestamp, not a minute bucket, so a same-day cutoff would drop the final 59 seconds), so consecutive windows partition the result set with no gap — the mechanism for reaching matches past the `start` pagination ceiling. Malformed or inverted bounds throw `invalid_date_range`. [#27](https://github.com/cyanheads/arxiv-mcp-server/issues/27)

## Fixed

- **`arxiv_search`**'s `enrichment.effectiveQuery` now echoes the service's `SearchResult.effective_query` — populated on both the live and mirror search paths by a shared query-composition function — instead of reconstructing the string from `input.query` in the handler, which silently dropped the `cat:` category wrapper on filtered searches. [#20](https://github.com/cyanheads/arxiv-mcp-server/issues/20)
- **`category`** on `arxiv_search` now accepts a bare archive code (`astro-ph`, `cond-mat`, `cs`, `math`, …) and matches its whole subtree — subject classes plus the legacy flat papers filed before the archive was subdivided — instead of matching nothing. `categorySearchTerm` / `categorySubtree` in `categories.ts` derive the searchable set and the live/mirror operand from the taxonomy, so the two paths cannot disagree on what a code means. [#32](https://github.com/cyanheads/arxiv-mcp-server/issues/32)
