# 1.8.0 — 2026-10-26

## Added

- **`arxiv-guide` Agent Skill** — a published skill for resolving citations to arXiv IDs, author and category searches, following a paper's versions, and reading long papers section by section, served over MCP as `skill://arxiv-guide/SKILL.md` (listed in `resources/list`, with the `skill://{+path}` template and the skills extension advertised at `initialize`) and shipped in the npm package, the Docker image, the `.mcpb`, and plugin installs (`createApp({ skills })`, mcp-ts-core 0.13.18).
- **Root `plugin.json` and `mcp.json`** — the Agent Plugins 1.0.0 root pair, from the mcp-ts-core 0.13.18 template.

## Changed

- **`arxiv_search_papers`'s `Query:` trailer** in `content[]` shows the effective query as a code span, so a copied query carries no backslash escapes; `structuredContent.effectiveQuery` is unchanged (mcp-ts-core 0.13.18, [cyanheads/mcp-ts-core#785](https://github.com/cyanheads/mcp-ts-core/issues/785)).
- **The `.mcpb` no longer carries** `src/`, `docs/`, `scripts/`, `changelog/`, `.github/`, `.vscode/`, a local `data/` mirror database, node-gyp build files under `node_modules/better-sqlite3/build/` that recorded the packing machine's paths, or the framework's build-only files: root-anchored `.mcpbignore` lines and the mcp-ts-core 0.13.18 `clean-mcpb` ([cyanheads/mcp-ts-core#508](https://github.com/cyanheads/mcp-ts-core/issues/508), [cyanheads/mcp-ts-core#783](https://github.com/cyanheads/mcp-ts-core/issues/783), [cyanheads/mcp-ts-core#791](https://github.com/cyanheads/mcp-ts-core/issues/791)).
- **`bunfig.toml`** `minimumReleaseAge` 3 days → 1 day (mcp-ts-core 0.13.17 template); framework skills re-synced, including the new `add-skill`, and the bug-report form uses one Environment table (0.13.17).
- **Mirror store search tests** build their term-less reference result sets once in setup instead of inside a timed test (#95).

## Fixed

- **The HTTP transport no longer retains about 71 KiB per request** — 1.7.2 shipped on mcp-ts-core 0.13.16, which leaked that much per request under sustained traffic; mcp-ts-core 0.13.17 gives each exchange its own abort controller, released when its response ends ([cyanheads/mcp-ts-core#786](https://github.com/cyanheads/mcp-ts-core/issues/786)).

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.13.16` → `^0.13.18` (brings `@modelcontextprotocol/server` 2.3.1 → 2.4.0, from 0.13.17)
- `@biomejs/biome` `^2.6.2` → `^2.6.3` (dev); `@types/bun` `^1.4.3` → `^1.4.4` (dev); `ignore` `^7.0.13` → `^7.0.14` (dev)
